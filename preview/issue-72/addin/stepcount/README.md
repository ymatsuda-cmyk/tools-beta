# ステップ数集計アドイン

フォルダに取引先名を割り当て、ダッシュボードで全体像を把握しつつ、取引先・拡張子のピルで絞り込んだファイル一覧を確認できる Excel 作業ウィンドウアドインです。集計はすべてアドイン側のメモリで行い、シートには「割当」「コード」「出力結果」だけを置きます。

## ファイル構成

```
step-count-addin/
  manifest.xml        アドインのマニフェスト
  package.json        ローカル配信用のスクリプト
  src/
    taskpane.html     作業ウィンドウのマークアップ
    taskpane.css      スタイル
    taskpane.js       読み込み・割当解決・集計・出力
```

## ブックの準備

シート名は `taskpane.js` 冒頭の `SHEET` で変えられます。

### `データ`（必須・1行目はヘッダー）

| A: パス | B: 拡張子 | C: 総ステップ | D: 実ステップ |
|---|---|---|---|
| `10.1.1.3\winntdir\delphi5\Amp\PROC.pas` | pas | 3989 | 2766 |

- 区切りは `\` でも `/` でも構いません。先頭の `\\` は自動で落とします。
- B列が空の場合はファイル名の拡張子を使います。
- C・D列は数値でも `1,234` のような文字列でも読めます。
- 表示・集計にはすべて **実ステップ（D列）** を使います。総ステップは現在のUIには出てきません。

### `割当`（無ければ初回起動時に自動作成）

| A: フォルダパス | B: 取引先名 |
|---|---|
| `10.1.1.3\winntdir\delphi5\Amp` | ライターム商事 |

**最長一致した祖先が勝つ**方式です。特定のフォルダだけ継承を断ち切りたい場合は、そのフォルダのB列に`（解除）`という印が内部的に書き込まれます（割当タブの操作から自動で行われます。詳しくは「割当」タブの節を参照）。

### `コード`（無ければ初回起動時に自動作成）

| A: 取引先 | B: 画面 | C: 設定 |
|---|---|---|
| ライターム商事 | frm | ini |
| ハンター製菓 | dfm | cfg |
| （空欄可） | | |

A列・B列・C列は**独立したリスト**です。行を対応させる必要はありません（どれか1つだけ埋まっていても構いません）。

- **A列（取引先）**：割当タブの「編集する取引先」ピル、ソース一覧の取引先ピル、ダッシュボードの取引先別グラフの並び順の元になる、取引先の正式な一覧です。まだファイルが1つも割り当てられていない取引先も、ここに書いてあれば0件のバーとして表示されます。
- **B列（画面）**：「画面定義」区分に分類する拡張子の一覧です。`.`は付けても付けなくても構いません（`frm`でも`.frm`でも同じ扱いになります）。
- **C列（設定）**：「設定」区分に分類する拡張子の一覧です。書式はB列と同じです。

どちらにも載っていない拡張子は「ソースコード」区分になります。区分の詳細は下の「ダッシュボード」の節を参照してください。

割当タブの「取引先を追加」から新しい取引先名を登録すると、この`コード`シートのA列に自動で1行追記されます（B列・C列には触れません）。

## 起動手順

```
cd step-count-addin
npm run cert
npm start
```

サイドロード後、リボンの「ステップ数集計」から作業ウィンドウを開きます。タブは次の3つです。

## タブ構成

### ダッシュボード（既定で表示）

上部に「合計」「ソースコード」「画面定義」「設定」の4つのボタンが並びます。**この4つはダッシュボードとソース一覧で共通の選択状態です**。どちらのタブで押しても、もう一方のタブにもそのまま反映されます。

- **合計**：取引先が割り当てられている全ファイルが対象です。
- **ソースコード**：`コード`シートのB列（画面）・C列（設定）のどちらにも載っていない拡張子のファイルだけが対象です。
- **画面定義**：`コード`シートのB列（画面）に載っている拡張子のファイルだけが対象です。
- **設定**：`コード`シートのC列（設定）に載っている拡張子のファイルだけが対象です。

各ボタンにはそのファイル数（取引先が割り当てられているものだけ、未割当を除く）が表示され、選んでいるボタンが緑色でハイライトされます。

下の「合計ステップ」「取引先数」のカードと、「取引先別」「拡張子別」の内訳は、すべて**選んでいる区分に絞った数字**になります。「取引先別」は（未割当）を一覧に出しません。`コード`シートに登録済みで、まだファイルの割当がない取引先も0件のバーとして表示されます。

「ダッシュボード」タブをクリックすると、ソース一覧側の拡張子ピルの選択は「すべて」にリセットされます。

### ソース一覧（旧「集計」タブ）

上部の4区分ボタン（ダッシュボードと共通）→ 取引先ピル → **ステップ／ファイル数のカード** → 拡張子ピル → 一覧、という並びです。**（未割当）のファイルは対象外です**（未割当は件数が大きくなりがちで、一覧の反応が遅くなる主因だったため常に除外しています。未割当の総量はダッシュボードの「合計ステップ」と「取引先別」の合計との差分から把握できます）。

- 取引先ピルは`コード`シートのA列（取引先）に登録されている名前の一覧です。まだファイルの割当がない取引先も選べます（選ぶと該当0件になります）。
- **区分ボタンのファイル数は、取引先ピルで絞り込んでいる場合その取引先だけの件数になります**（「すべて」のときは全取引先の合計）。ダッシュボード側の区分ボタンは常に全取引先の合計です。
- 取引先ピルを選ぶと、拡張子ピルの選択肢がその時点の絞り込みに応じて絞られます。取引先を変えると拡張子は「すべて」に戻ります。
- **区分ボタン（合計以外）を選ぶと、その区分に属さない拡張子は拡張子ピルから消さず、選べないグレー表示（打ち消し線）にします**。選べなくなった拡張子がそのとき選択中だった場合は、自動的に「すべて」に戻します。
- フォルダ単位の絞り込みは行いません。
- 一覧は フォルダ／ファイル名／拡張子／ステップ数 の4列に分かれています。既定の並びはフォルダの昇順です。列見出しをクリックするとその列で並べ替え、同じ列をもう一度クリックすると昇順・降順が切り替わります（見出しの ▲▼ が現在の並びを示します）。
- **「出力」は、今画面に表示している一覧をそのまま**（区分・取引先・拡張子の絞り込み、並び順すべてを反映した状態で）、`出力`という別シートに書き出します（今見ている画面のシートは上書きしません）。集計や構成比は計算せず、フォルダ／ファイル名／拡張子／ステップ数の生データをそのまま並べるだけです。ボタンを押すたびに`出力`シートの内容は作り直されます。

### 割当

「編集する取引先」のピルで、今から編集する取引先を1つ選びます。ピルの並びは、ステップ数の多い取引先が先、`コード`シートに登録済みだがまだファイルの割当がない取引先（0件）はその後にアルファベット・五十音順で続きます。

まだ`コード`シートに載っていない取引先を扱いたいときは、ピルの下の「新しい取引先名」に入力して「取引先を追加」を押してください。`コード`シートのA列に自動で追記され、その場でピルに追加され、編集対象になります（Enterキーでも追加できます）。同名がすでにある場合は追加せず、その取引先の編集に切り替えるだけです。

ツリーのチェックは「このフォルダが実際にその取引先の集計に入っているか」（祖先からの継承も含めて）をそのまま表します。ダッシュボード・ソース一覧が数えているものと画面のチェック状態は常に一致します。

- **チェックを入れる** → そのフォルダと配下すべてに、この取引先名を直接書き込みます。
- **チェックを外す** → そのフォルダと配下から、この取引先を外します。祖先フォルダがまだこの取引先のままで、外さないと継承で戻ってしまう場合は、内部的に継承を断ち切る印を書き込みます（画面には特別なバッジは出ず、見た目は「未割当」と同じです）。それ以外の場合は、単にエントリを削除します。

バッジは2種類だけです。

- 今編集中の取引先名（緑）— チェックが入っている
- 別の取引先名（グレー）— すでに他の取引先の集計に入っている（直接でも継承でも）。チェックを入れると上書きされる

操作はコントロール行の「未保存の変更 N 件」に反映され、下部の「保存」を押すまで Excel には書き込まれません。「取り消し」で編集開始時の状態に戻せます。

「展開」に0階層（すべて閉じる）を追加しました。隣の「選択のみ表示」を押すと、現在チェックされているフォルダへ辿り着く経路だけを開き、それ以外は閉じます。チェックした場所を大きなツリーの中から見失ったときに使ってください。

割り当てるフォルダの数が多いほど、保存時に `割当` シートへ書き込む行数も増えます（配下すべてに個別の行ができるため）。読み込み時と同じくチャンク分割で書き込むので、数千行になっても通常は数秒以内に終わります。画面は保存後に対象フォルダのバッジが変わるだけで、データシートの読み直しは行いません（スクロール位置も保たれます）。Excel 側で `データ` シートや `割当` シートを直接編集した場合だけ、ステータス行の ↻ ボタンで読み直してください。

## 実装メモ

- 読み込みは `getUsedRange()` の行数を測ってから `CHUNK`（既定2000行）ずつ読み、以降はすべて JS 側で処理します。行ごとに `context.sync()` を呼ぶ実装は数千行で分単位になるため避けています。`コード`シートも同じ `readArea()` で読みますが、想定件数が少ないため通常は1回で読み切ります。
- `コード`シートは `parseCodeSheet()` がA列（取引先）・B列（画面）を独立したリストとして読みます。行の対応関係は前提にしていないので、どちらか一方だけ埋まっていても構いません。結果は `state.codeVendors`（配列）・`state.screenExts`（小文字・`.`除去済みの Set）に格納されます。
- 各データ行には `f.isScreen`（`state.screenExts.has(f.ext)`）・`f.isConfig`（`state.configExts.has(f.ext)`）を持たせています。`fileCategory(f)` がこの2つのフラグから「screen」「config」「source」のどれかを1つ返し、`extCategory(ext)` は拡張子単体から同じ判定をします。`state.category`（`"total"` / `"source"` / `"screen"` / `"config"`）はダッシュボードとソース一覧で共有する1つの値で、`aggregateAll()` と `filteredSourceRows()` の両方がこれでフィルタします。4つのボタンは `renderCategoryButtons(hostId, vendorFilter)` が両タブ共通で描画し、クリックで呼ばれる `setCategory()` が `state.category` を更新してから両タブを再描画します。件数計算（`categoryCounts(vendorFilter)`）は `vendorFilter` を渡すと、その取引先だけに絞った件数を返します。ダッシュボードは常に `vendorFilter` なし（全取引先）で呼び、ソース一覧は `state.srcVendor` を渡すので、取引先ピルの絞り込みがボタンの件数にも反映されます。
- ソース一覧の拡張子ピルは `extOptions()` では絞り込まず、`pillRow()` の `isDisabled` 述語（`state.category !== "total" && extCategory(ext) !== state.category`）でグレー表示にするだけです。一覧から消してしまうと「なぜこの拡張子が選べないのか」が分かりにくいため、選択肢自体は残して非活性にする形にしています。区分ボタンを切り替えて今の拡張子選択が非活性になる場合は、`setCategory()` が自動的に「すべて」へ戻します。
- `switchTab()` で「ダッシュボード」を選んだときは `state.srcExt` を「すべて」に戻してから描画します。取引先・区分の選択はタブをまたいでも保持されます。
- ファイル1件ごとの取引先解決（ダッシュボード・ソース一覧・出力用）は今まで通り `lookup()` の最長一致（祖先を遡って最初に一致したエントリを採用）です。これは変えていないので、過去に「最上位フォルダだけに割当」していたデータも問題なく読めます。
- 取引先の一覧は `allVendorNames()`（`コード`シートのA列 ∪ `割当`シートに実際に登場する取引先名）が担います。ソース一覧の取引先ピルはこれをそのまま使い、割当タブのピル（`assignPillOptions()`）は `aggregateAll(false)` の結果（`コード`シートの取引先で事前に0件シードした上でステップ数集計）をそのまま使うので、未使用の取引先も一覧の後方に出てきます。
- 新規取引先の追加は `addNewVendor()` → `appendCodeVendor()` が担当します。`コード`シートの使用範囲の高さから次の空き行を求め、A列にだけ1セル書き込みます（B列の画面リストには触れません）。
- 割当タブのチェックボックスは `computeEffectiveVendors()` が担います。ツリーを1回だけ辿りながら、各フォルダが実際にどの取引先になるか（自分自身のエントリ、なければ祖先から継承、`UNASSIGN_MARK` があればそこで打ち切り）を求め、`committedSetFor(vendor)` はその結果から該当パスだけを取り出します。これにより、チェック状態は常に「ダッシュボード・ソース一覧が数えている内容」と一致します。
- チェックの伝播は `toggleDraft()` が配下すべてに同じ状態（true/false）を書き込みます。保存前は `draftDiff()` が「新たにチェックされたパス」「チェックが外れたパス」を求め、保存時にまず素直に追加・削除を反映します。そのあと `computeEffectiveVendors()` をもう一度呼び、**チェックしていないのに継承で editVendor になってしまっているフォルダ**を全部洗い出して、そこだけ `UNASSIGN_MARK`（内部的な打ち消し）を書き込みます。これは「これから新しく上位フォルダへ割り当てる」ケースで、チェックを外していた配下に継承が漏れるのを防ぐためのものです（保存前の状態と比較するだけの単純な差分だと、このケースを見逃していました）。画面上はどちらも同じ「未割当」の見た目になり、区別は表示されません。
- 「展開」に0階層を追加し、すべて閉じた状態から見られるようにしました。「選択のみ表示」ボタン（`focusChecked()`）は、現在チェックされているフォルダへ辿り着く経路だけを開き、それ以外は閉じます。
- 保存後は `refreshAssignments(changed)` が変更されたパスの配下だけ `lookup()` で再解決し、`markTree()` でバッジを付け直して再描画します。Excel からの読み直しは行わないので、7万行規模でも体感で終わります。
- ツリーの再描画では `host.scrollTop` を退避・復元しているので、保存後もスクロール位置が保たれます。
- `UNASSIGN_MARK`（`（解除）`という文字列）は、祖先からの継承を打ち切るためだけに使う内部的な印です。画面には専用バッジとして出さず、常に「未割当」と同じ見た目にしています。
- ダッシュボードは `aggregateAll()`、ソース一覧は `vendorOptions()` / `extOptions()` / `filteredSourceRows()` が担当します。ピルは実 DOM の `<button>` なので、キーボード操作（Tab / Enter / Space）も追加コードなしで機能します。
- ソース一覧の並び替えは `state.srcSort`（`{col, dir}`、既定は `folder` の `asc`）で保持し、`sortSourceRows()` が `filteredSourceRows()` の結果に適用します。列見出しは `setSourceSort(col)` を呼ぶ実 DOM の `<button>` で、同じ列を再度押すと昇順・降順を反転します。フィルタ・並び替えの条件が変わるたびに `renderSourceList()` を呼び直すだけなので、状態は常に一箇所（`state.srcSort` / `state.srcVendor` / `state.srcExt`）に集約されています。
- 出力（`exportSheets()`）は、その時点の `sortSourceRows(filteredSourceRows())`（＝ソース一覧に表示されているのと同じ行・同じ並び順）をそのまま `出力` シートに書き込みます。集計・構成比の計算は行いません。`putSheet()` は毎回シートの使用範囲をクリアしてから書き直すので、手で列を足しても次の出力で消えます。加工したい場合は別シートにコピーしてから行ってください。

## 拡張しやすい箇所

- ダッシュボードの取引先別・拡張子別バーをクリックしてソース一覧に絞り込み状態で遷移させたい場合は、`statRow()` にクリックハンドラを足し、`switchTab("source")` の前に `state.srcVendor` 等をセットします。
- 取引先ピルが多くなり折り返しが窮屈な場合は、`pillRow()` の出力元に検索用テキスト入力を足し、`vendorOptions()` の結果をその場でフィルタします。
- コメント率（総 − 実）を出したい場合は、`データ`シートのC列（総ステップ）を各集計関数に足し込みます。
