# 新規LLMエンドポイント追加プロンプト

このプロンプトを、別のLLM（Claude等）セッションにそのまま貼り付けて使用する。
`SYSTEM_SPEC.md` を同じ会話に添付してから、これを送ること。

---

## 依頼内容

添付の `SYSTEM_SPEC.md` は、Kaggle無料GPU上でOllamaを動かし、GAS経由で起動制御、
GitHub Pagesの静的チャットアプリから利用する既存システムの仕様書です。

このシステムに**新しいLLMエンドポイントを1つ追加**したいです。
既存のgemma4エンドポイントとは完全に独立した、別のKaggleアカウント・別のGASプロジェクト・
別のngrokアカウントを使う構成にしてください（1エンドポイント=1組が本システムの原則です）。

### 新規エンドポイントの情報

以下を埋めて渡す：

```
表示名: 
モデル名（Ollama上の呼称）: 例) qwen3:27b
Kaggleユーザー名: 
Kaggleカーネルスラグ: 例) qwen3-27b
GPU種別想定: 例) T4x2 / P100
このエンドポイント専用の識別子(id): 例) b
ngrok固定ドメイン: 取得済み/未取得
画像対応が必要か: はい/いいえ
音声対応が必要か: はい/いいえ
想定num_ctx: 
使用予定のKaggle Dataset（モデル本体）: 作成済み/これから作る
```

### 依頼したい成果物

1. **`kaggle_controller_single.gs`**（既存のものを流用可能。CONFIGの値だけ変える前提で、コード自体の変更は不要なはず。変更が必要なら差分を明示）
2. **`proxy_py.html`**（既存のものを流用可能。`DEFAULT_MODEL`はプレースホルダ`__MODEL__`経由なのでコード変更は基本不要。モデル固有の対応が必要な場合のみ差分を明示）
3. **新規GASプロジェクトに設定する`CONFIG`のJSON**（プレースホルダを埋めた完成形）
4. **データセット作成手順**（モデルがまだ無い場合。CPU/Internet Onでの`ollama pull`スクリプト。画像対応が必要な場合は`ollama show`でvision確認する手順を含める）
5. **アプリ側に追加するプロファイルのJSON**（`gemma-chat-js`の設定→「JSONで一括編集」に貼る形式）

### 前提として厳守してほしいこと（SYSTEM_SPEC.mdの「7. 既知の落とし穴一覧」を必ず踏まえる）

- `proxy_py.html`をHTMLファイルとして保存する際、コード中に`<`比較演算子を含めない（`&lt;`エスケープ事故を防ぐため）。ループが必要な場合は`for ... in range(...)`方式を使う
- `gas()`関数の呼び出しはUser-Agentヘッダとリトライを維持する
- `gas('started', ...)`の呼び出しは必ずtryで囲み、失敗してもポーリングループに到達できるようにする
- モデルが画像対応かどうかは、思い込みではなく`ollama show <model>`の`Capabilities`欄で`vision`の有無を実際に確認してから進める
- CONFIGの`controlToken`と`proxyApiKey`は、既存エンドポイントとは別の値を新規生成する（`openssl rand -hex 16`）
- Kaggle APIキーなど機密情報は、やり取りの中でスクリーンショットや平文で共有しない。共有された場合は速やかに失効・再発行するよう案内する

### 検証手順として含めてほしいもの

新規デプロイ後、以下の順で確認できるチェックリストを提示すること：

1. `?action=ping` で疎通確認
2. `testProps()` / `testConfig()` で必須項目確認
3. `testNotebookSource()` でJSON妥当性確認
4. 実際に起動し、ログで以下を順に確認：
   - `VISION:` の判定結果
   - `Model ready (試行N回目)`
   - `gas started -> {'success': True}`
   - `Nmin alive` のポーリングログ
5. GAS側`testStatus()`で`proxyAlive: true`かつ`modelReady: true`を確認
6. アプリのサイドバーで新エンドポイントが「稼働中」表示になることを確認
7. 実際にチャットを1往復させ、`usage.prompt_tokens`が返ることを確認
8. 「停止」を押し、30秒以内に停止し`稼働時間`が記録されることを確認
